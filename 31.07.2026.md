## ТАКТ 2. РЕЗЕРВАЦИЯ И ТРАНСФОРМАЦИЯ ДАННЫХ (SQL / СУБД)

### Шаг 12. Развертывание снайперской SQL-очистки (DML)
*   **Действие:** В редакторе SQL DBeaver написан и выполнен запрос фильтрации:
    ```sql
    SELECT tx_id, user_id, amount
    FROM raw_transactions
    WHERE amount IS NOT NULL AND amount > 0;
    ```
*   **Что увидел пользователь:** Математический движок PostgreSQL отсек технические сбои `[NULL]` и отрицательный возврат `-4500`. На экране зафиксирована чистая реляционная сетка из 2 строк.
*   **Зачем это сделано:** Выполнение ТЗ финансового директора. Удаление системного шума и изоляция чистых приходов для расчета честной валовой выручки.
*   **КАПКАН №5 (Регистр кавычек):** Использование двойных кавычек `as "сырые_транзакции"` для псевдонима таблицы. В PostgreSQL это принудительно зажимает регистр букв в RAM и ломает последующие связанные запросы `WHERE`. 
*   **Решение инцидента:** Код принудительно приведен к стандарту индустрии — псевдонимы таблиц прописаны латиницей в нижнем регистре без кавычек.

### Шаг 13. Запечатывание вычисляемого моста (Data Mart)
*   **Действие:** На основе проверенного запроса в ядро базы данных внедрено Представление:
    ```sql
    CREATE VIEW v_clean_transaction AS
    SELECT tx_id AS id, user_id, amount AS количество
    FROM raw_transactions
    WHERE amount IS NOT NULL AND amount > 0;
    ```
*   **Зачем это сделано:** Создание защитной прослойки данных. Витрина `VIEW` сохраняет формулу очистки внутри СУБД. Теперь Power BI подключается не к грязной таблице, а к стерильному представлению, которое на лету фильтрует хаос при каждом обновлении.

## ТАКТ 3. ПРИЕМКА И ВИЗУАЛИЗАЦИЯ (BI-КОНТУР)

### Шаг 14. Настройка сетевого шлюза к СУБД
*   **Действие:** В Power BI Desktop запущен коннектор баз данных PostgreSQL. Проложен сетевой адрес `localhost:5433` и указано целевое имя базы `postgres`.
*   **Зачем это сделано:** Переход от ручного импорта файлов к промышленному шлюзованию данных (Live Data Connection).
*   **КАПКАН №6 (Сетевая опечатка):** Пользователь ошибочно вбил имя базы с двойной «s» (`postgress`), что привело бы к сбою аутентификации.
*   **Решение инцидента:** Произведен откат на один экран назад, адресная строка принудительно синхронизирована с чертежами ИТ-лаборатории.

### Шаг 15. Авторизация в периметре СУБД
*   **Действие:** Попытка входа с паролем `postgres` заблокирована. На основе поднятой инструкции пускового bat-файла поле пароля оставлено абсолютно **ПУСТЫМ**. Логин: `postgres`.
*   **Зачем это сделано:** Синхронизация с политикой безопасности локального сервера. Портативная СУБД настроена в режиме доверия (`trust`), что ускоряет разработку и исключает затыки шифрования в изолированной песочнице.

### Шаг 16. Захват SQL-витрины в оперативную память (RAM)
*   **Действие:** В окне «Навигатор» проигнорирован сырой слой `raw_transactions`. Галочкой отмечен только объект `public.v_clean_transaction` и запущен импорт (`Load`).
*   **Зачем это сделано:** Оптимизация памяти. Аналитик полного цикла экономит RAM BI-системы, затягивая на холст только подготовленные и агрегированные слои данных.

### Шаг 17. Материализация финального пульта управления (KPI)
*   **Действие:** Написана мера вычисления на лету на языке DAX, результат выведен на холст через элемент «Карточка»:
    ```dax
    Очищенная Выручка = SUM('v_clean_transaction'[количество])
    ```
*   **Что увидел пользователь:** Карточка отобразила точное кумулятивное значение: **3,80 тыс.** (`3800`).
*   **Зачем это сделано:** Финал спринта. Тяжелый инженерный ETL-конвейер скрыт от глаз бизнеса. Руководство получило реактивный, очищенный от ошибок ИТ-системы пульт управления выручкой. Математический баланс сошелся копейка в копейку по всей трубе процесса.

### Шаг 18. Безопасный деплой и остановка серверов
*   **Действие:** Файл отчета зафиксирован на диске в формате `01_fintech_dashboard.pbix`. Программа DBeaver закрыта. В терминале `start_database.bat` отправлена команда `stop` через клавишу Пробел. Веб-сервер Jupyter принудительно заглушен в Anaconda Prompt через `Ctrl + C`.
*   **Зачем это сделано:** Защита файловой системы от Database Corruption. СУБД принудительно сбросила кэш вычислений из RAM на жесткий диск до закрытия портов.
