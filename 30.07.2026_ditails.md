## Шаг 4. Формирование сырых векторов (Тестовая заглушка)

* Команда к действию: Во вторую пустую ячейку Jupyter руками ввести код создания списков сырых данных и запустить через Shift + Enter:
```python
tx_ids = list(range(1001, 1006))

```
* Зачем это сделано: Имитация сбоя ИТ-системы для техзадания финансового директора. Пропуски None закладывают будущие пустоты, а отрицательное число -4500 — операцию возврата, которая сейчас искажает валовую выручку. Создание микро-заглушки на 5 строк позволяет отладить логику без нагрузки на процессор.

## Шаг 5. Сборка и фиксация сырого DataFrame

* Команда к действию: В третью ячейку ввести код сборки матрицы и вывода её на экран:
```python
raw_data = {

    'user_id': user_ids,
    'amount': amounts

df
```
* Что увидел пользователь: На экране материализовалась таблица из 5 строк, где вместо None автоматически встали официальные маркеры пустоты Pandas — NaN (Not a Number).
* Зачем это сделано: pd.DataFrame берет словарь связей и жестко сшивает изолированные списки по строкам и индексам, превращая их в единую связанную структуру таблицы.

```python

```

## ТАКТ 2. РЕЗЕРВАЦИЯ И СТРУКТУРИРОВАНИЕ ДАННЫХ (SQL / СУБД)
## Шаг 7. Активация автономной СУБД

* Команда к действию: Зайти в корневую папку ИТ-лаборатории, дважды кликнуть по файлу start_database.bat (запуск PostgreSQL 16 на порту 5433). Окно не закрывать. Открыть dbeaver.exe. Кликнуть правой кнопкой по соединению localhost:5433, нажать «Соединить». Открыть окно ввода кода через Ctrl + Alt + Q.
* Зачем это сделано: Развертывание реляционного слоя. Переход от нестабильных текстовых файлов к промышленному стандарту безопасного централизованного хранения.

## Шаг 8. Разметка реляционного сектора хранения (DDL)

* Команда к действию: В белое окно редактора DBeaver ввести код создания таблицы и запустить его через комбинацию Ctrl + Enter:
```sql
CREATE TABLE raw_transactions (
    tx_id INT,
    user_id INT,
    amount NUMERIC
);
```
* Что увидел пользователь: Лог в нижней панели DBeaver подтвердил успешную обработку запроса за 0,111 секунды.
* Зачем это сделано: СУБД требует жесткого описания структуры до начала загрузки. Тип NUMERIC выбран снайперски — в отличие от FLOAT, он гарантирует абсолютную точность вычислений финансового контура без округлений процессора.

## Шаг 9. Аппаратный сброс кэша интерфейса (Борьба с аномалией)

* КАПКАН №3 (Скрытая таблица): Пользователь прошел по цепочке левого навигатора: postgres -> Базы данных -> postgres -> Схемы -> public -> Таблицы. Но созданной таблицы raw_transactions внутри папки не оказалось — там была видна только старая таблица commercial_report.
* Команда к действию: Кликнуть правой кнопкой мыши по желтой папке «Таблицы» и нажать кнопку «Обновить (Refresh)» (или клавишу F5).
* Результат: Кэш DBeaver перезагрузился из RAM СУБД, и таблица raw_transactions мгновенно материализовалась в списке.
* Зачем это сделано: Графический интерфейс не обновляет дерево папок автоматически. Сброс кэша синхронизировал экран с реальным состоянием диска СУБД.
